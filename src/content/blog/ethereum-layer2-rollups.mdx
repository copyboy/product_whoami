## 主线收官之后，先讲最贴日常体验的一件事

[收官篇](/blog/dao-case-studies)的结尾说：专栏到此完结，愿你带着这套地图继续往深处走。地图画完了，但用过这张地图的人都会撞上同一堵墙：**在以太坊主网做任何事，都贵**。转账贵、换币贵、 mint 一个 NFT 更贵——[Gas 篇](/blog/ethereum-gas-fees)算过账：主网 Gas 通常在个位数到几十 <GlossaryTerm term="gwei" /> 波动，而同样一笔操作放到 L2 上，单价往往不足 0.01 gwei，差距可达 1000 倍。

这个 1000 倍差距不是魔法，是一整套叫 **Layer2 扩容（Rollup）** 的架构红利的最终表现。它也是番外三篇（扩容、稳定币、钱包与账户抽象）里最贴日常体验的专题——你每次在 L2 上签交易省下的钱，都来自这一篇要拆的机制。先把主线里埋的线头收拢：<GlossaryTerm term="Layer2" /> 词条说过它「通过 Rollup 技术提升吞吐量、降低费用」；<GlossaryTerm term="Rollup" /> 词条说过它「将大量交易打包后在链下执行，仅将压缩后的数据或证明提交到主网」。本篇就把它拆开：为什么需要它、它怎么在不动 L1 的前提下把费用打下来、以及 Optimistic 与 ZK 两条路线到底在争什么。

---

## 不可能三角：为什么 L1 不肯「直接调大参数」

扩容最直觉的方案是：把区块调大一点、出块调快一点，吞吐不就上去了？以太坊不是做不到，是不肯做。原因是一道选择题——<GlossaryTerm term="不可能三角" />（区块链三难困境）：**去中心化、安全性、可扩展性，三者不可同时兼得**。

先说清楚「提高区块参数」意味着什么：每个区块更大（装更多交易）、处理更快，节点要跟上链的步伐，磁盘、带宽、CPU 的硬件门槛就随之抬高。[比特币网络实战篇](/blog/bitcoin-network-in-practice)讲过<GlossaryTerm term="全节点" />的角色——它们下载全部区块数据、从第一笔交易开始独立验证每一条规则，是「不要信任，去验证」的物理载体。**全节点越多，伪造账本越无处遁形**；而全节点的数量，取决于普通人用一台普通电脑还跑不跑得动它。

于是天秤倾斜的方向就很清楚：

```text
不可能三角下的「直接扩容」：

  提高区块参数（更大/更快）
        │
        ▼
  单节点硬件门槛抬高 ──▶ 能独立验证的节点变少
        │
        ▼
  验证权事实上集中到少数高配节点
        │
        ▼
  去中心化被换成了吞吐 —— 三角的一角塌了
```

这不是假设：历史上多条走「大区块」路线的链，最终都不同程度地把验证权让渡给了少数矿池与机房。以太坊的选择相反——**宁可慢，也要保住「一台普通电脑能验证整条链」这条底线**，扩容另寻出路。出路就是：L1 参数不动，把「执行」搬走。

---

## Rollup 的核心思路：执行搬下链，数据交回 L1

Rollup 的思路一句话就能说完：**交易的执行搬到链下（L2）做，执行所需的数据与证明交回链上（L1）存**。

拆开看各方的分工：

```text
Rollup 架构的 L1/L2 分工（示意）：

  用户 ──▶ L2（Rollup 链，执行层）
             │  交易在这里被打包、执行、算出新状态
             │  执行环境便宜（不用全网共识逐笔确认）
             │
             │  每批次：压缩后的交易数据 + 证明
             ▼
           L1（以太坊主网，结算与数据层）
             │  数据进入区块/blob：任何人都能取回完整数据
             │  证明接受挑战或验证：L2 的结果可被 L1 裁决
             │
             └─▶ 安全锚：L2 的账本最终由 L1 的共识保护
```

关键的第七行——也就是「数据交回 L1」——是整个架构的安全锚，术语叫<GlossaryTerm term="数据可用性" />（Data Availability，DA）：**任何人都能从 L1 取回 Rollup 的完整交易数据**。它的分量在于：执行可以搬下链，数据必须留链上。假如数据不公开，只有 Rollup 运营者自己知道完整账本，其他所有人都只能「它说什么我信什么」——独立验证无从谈起，去中心化验证在 L2 这一层就断了。数据留在 L1，意味着哪怕 L2 的运营者作恶、宕机、消失，社区也能凭 L1 上的数据把账本重建出来、继续验证。**这就是「Layer2 的安全来自 Layer1」这句话的准确含义：借的不是 L1 的算力，是 L1 的数据可用性与裁决权。**

那「证明」交回 L1 是怎么工作的？这里正是两条路线的分水岭。

## 两条路线：Optimistic vs ZK

L1 拿到 L2 提交的状态结果后，要回答同一个问题：**这个结果对不对？** 两条路线给了相反的答案——一条假设它对、错了再罚（欺诈证明），一条直接证明它对（有效性证明）。

| 维度 | Optimistic Rollups | ZK Rollups |
|------|-------------------|------------|
| 核心假设 | 乐观假设交易有效 | 每批附带有效性证明 |
| 验证方式 | 欺诈证明：挑战期内任何人可提交作弊证据 | 有效性证明：L1 验证数学证明通过即生效 |
| 退出周期 | 约 7 天挑战期后最终确认 | 即时退出，无等待期 |
| 主要实现 | Arbitrum、Base、Optimism | zkSync Era、Starknet、Polygon zkEVM |

<GlossaryTerm term="Optimistic Rollups" /> 的机制像一个保证金制度：运营者先假定全部交易有效、直接出结果，但结果要经过约 7 天的挑战期——期间任何人发现作弊，都可以向 L1 提交欺诈证明；一旦证实，作弊批次被回滚，作恶者被罚。代价是把「信任」换成了「等待」：从 L2 把资产退回 L1，需要等挑战期走完。

<GlossaryTerm term="ZK Rollups" /> 则不赌人性：每批交易附带一个零知识有效性证明，L1 验证证明通过才接受结果——**数学上保证了提交的状态就是执行的真实结果**，因此没有挑战期、没有等待，退出是即时的。

<Highlight type="info">
「7 天挑战期」常被误读成 Optimistic 路线的缺陷，更准确的理解是**安全假设的成本**：它买的保险是「任何人都能挑战作弊」，而保险生效需要给挑战者留出反应时间。研究报告的口径也在此给出方向性判断：ZK Rollups 是未来——无 7 天挑战期、即时退出、隐私友好；但在当下，Optimistic 阵营凭借先发与 EVM 兼容性仍承载着大部分 L2 活动。
</Highlight>

## blob：1000 倍费用差距的最后一环

回到开篇的数字：同样一笔操作，主网个位数到几十 gwei，L2 不足 0.01 gwei，差距可达 1000 倍。这笔账在[Gas 篇](/blog/ethereum-gas-fees)算过机制，这里只收拢结论——L2 便宜不是某一层的折扣，是三段结构的叠加：

```text
一笔 L2 交易的成本构成（示意）：

  ① 执行在 L2 链下：不用全网每个节点逐笔重放，执行单价天然便宜
  ② 数据发布走 blob：单独计价的市场，与主网交易拥堵脱钩
  ③ blob 自动过期：数据只保留约 18 天即删除，不为永久存储付费
```

其中②③就是 <GlossaryTerm term="Blob" />（EIP-4844，Dencun 升级引入）：主网开辟一块独立的、按 blob gas 单独计价的数据空间给 Rollup 发数据——主网再堵，blob 市场未必堵；验证可用性不需要永久存储，数据约 18 天后自动删除，成本进一步压低。仅 blob 一项，就让 L2 的数据发布费用降低了 10-100 倍。

注意这套结构与上一节的呼应：blob 降的是「数据可用性」的价格，**没有削弱数据可用性本身**——18 天窗口足够任何关心 L2 账本的人取回数据、完成验证或重建。便宜的是「为验证所需的数据付的钱」，安全锚一根没松。这正是 Gas 篇结论的复述：Layer2 便宜不是因为牺牲安全，而是因为只为「验证所需的数据」付打折价，不为「主网的完整执行」付全价。

## 主流 L2 速览：两大阵营的定位

机制讲完，看一眼现役选手。阵营划分就是上一节的两条路线，定位信息与本站[研究报告](/web3/report)的口径一致：

**Optimistic 阵营（当下承载大部分 L2 活动）：**

- **Arbitrum** — 老牌头部，研究报告口径 TVL 约 $7.8B（数十亿美元量级），DeFi 深度是它的护城河
- **Base** — 交易所 Coinbase 背书，合规通道与消费级入口是差异化定位
- **Optimism** — 以 OP Stack 输出技术栈，Base 等多条链基于它构建，走「生态平台」路线

**ZK 阵营（技术叙事上的下一代）：**

- **zkSync Era** — Matter Labs 出品，ZK 路线的旗舰实现之一
- **Starknet** — 使用 STARK 证明系统，走自己的 Cairo 技术栈
- **Polygon zkEVM** — 主打 EVM 兼容，迁移成本最低的 ZK 选项之一

<Highlight type="warning">
口径说明：L2 市场的份额与 TVL 数字随行情波动很快，本篇只做定位级速览，量级表述以研究报告页为准，不引用任何精确的实时数字，也不构成任何投资建议。
</Highlight>

还有一条贯穿两个阵营的暗线值得点出：上面几乎所有名字，都出现在 [EVM 篇](/blog/evm-deep-dive)讲过的「一次编写、多链运行」兼容生态里——绝大多数 L2 选择直接实现 <GlossaryTerm term="EVM" /> 作为执行层。这不是巧合：开发者在哪里，流动性就在哪里；EVM 兼容性是以太坊生态最大的护城河，如今也是 L2 之间事实上的准入门槛。

## 总结：L2 是普通用户的实际入口

把这一篇收拢成四句话：

- **为什么不直接扩容 L1**：<GlossaryTerm term="不可能三角" />之下，提高区块参数等于抬高全节点门槛、用去中心化换吞吐——以太坊选择保住「普通电脑可验证」的底线
- **Rollup 怎么扩容**：执行搬到链下、数据与证明交回 L1；<GlossaryTerm term="数据可用性" />是安全锚——数据在 L1，独立验证就不断线
- **两条路线在争什么**：Optimistic 用 7 天挑战期换先发与兼容（Arbitrum/Base/Optimism），ZK 用有效性证明换即时退出（zkSync/Starknet）——后者被普遍看作方向
- **费用为什么低三个数量级**：执行链下便宜 + blob 单独计价 + 约 18 天自动过期，主网与 L2 差距可达 1000 倍，且不为省这点钱牺牲安全

对普通用户，这些机制汇总成一句朴素的话：**你实际使用以太坊的地方，大概率是 L2**。研究报告的「采用指标」也把这一点写得很直白——L2 日活钱包数是观察这个生态是否真正走向大众的核心指标之一（口径：大于 100 万量级）。主线里我们从转账讲到组织，番外则从体验往回拆原理：费用与入口的问题，Rollup 给出了工程答案。

但费用便宜只是「能用」，链上世界真正的「结算货币」另有其人——波动剧烈的 ETH 并不适合日常计价，这个角色由稳定币承担。它为什么是链上结算层、三种锚定机制各有什么代价，下一篇展开。
